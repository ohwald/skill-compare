# ADR-0001: 产品收敛为单库历史对比(移除跨 skill 对比)

- **状态**:已接受(2026-10-05 用户决策,2026-10-08 补记)
- **关联**:spec issue #8(已被本 ADR 取代并关闭)、`CONTEXT.md` 词汇表、design.pen v4·2

## 背景

v1 是多 skill 并排对比站,「版本模式」(双槽选中同一 skill 时进入的自比状态)只是子状态。2026-10-05 用户明确决策:默认且唯一的产品形态是**单 skill 历史对比**(参考 phistory 的模型:选对象 → 看版本时间轴 → 选两个版本 → 看 diff),删除两 skill 对比功能。

当晚的多轮重写全部失败,暴露的是结构性问题:双槽状态模型(`state.a`/`state.b`/`mode`)与"单库历史浏览"范式不兼容——每次在双槽代码上修补,交付物都退回旧范式(包括一次在交付清单里把"跨 skill 对比"当作新功能宣布)。最终回滚到 `aec47b1`(双槽 UI 的最后可用版)只是止血,不是目标形态。时间轴也在两个分支上各有硬伤:main 上是两个原生 range input 叠加、按版本序号均分;`feat/timeline-enhanced-v2`(`83ce9f4`)渲染了快捷按钮与刻度点但**没有任何事件绑定**,且重新引入了已否决的 ★ 星标。

## 决策

1. **产品只有一个交互模型**:选 skill → 时间轴 → 两个时间点 → diff。无模式切换、无双槽、无跨 skill 对比。
2. **时间轴是导航中枢**:按提交日期比例定位刻度(非版本序号)、落 tag 的提交带标签、双柄选取自动锚定最近提交、快捷范围(7/14/30/180 天)、缩放与平移、hover 反馈。作为独立组件先原型验收再集成,不在旧渲染函数上叠加补丁。
3. **现存双槽代码视为遗留起点**:main(= `aec47b1` 回滚版)是止血基线,目标是替换而非修补;`feat/timeline-enhanced-v2` 的时间轴增强因"渲染未绑定"不合并且作废。
4. **UI 改动的验收门槛**:无头浏览器 e2e 通过 + 设计评审通过;`tests/test_frontend_bindings.py` 守卫"渲染了但没绑定"这一事故类别。

## 后果

- `template/app.js` 的 slot/mode 代码路径待整体移除(见新 spec issue);在移除完成前,任何 UI PR 不得新增对它们的依赖。
- `CONTEXT.md` 词汇表已同步:时间轴为正式词汇;「版本模式」「两两对比」列为废弃。
- 构建产物带 build stamp(index.html meta + app.js `?v=` 缓存指纹),线上与本地的一致性可一键核对,杜绝"浏览器缓存"式误诊。
- 时间轴组件实现前,先出独立交互原型(`template/timeline.html`,纯静态可直开)交用户验收。
